# /session-rename — 세션명 자연 업그레이드

## JTBD

대화가 진행되며 주제가 더 구체화되거나 바뀌었을 때, 사용자가 나중에 세션을 찾기 쉬운 제목을 제안하고, 사용자가 동의한 경우에만 세션명을 변경한다.

## 핵심 원칙

1. **자동 변경 금지** — 세션명은 사용자의 기억 체계다. 조용히 바꾸지 않는다.
2. **제안은 가볍게** — 본 작업 흐름을 끊지 않는 한 문장으로 묻는다.
3. **후보 수는 상황별 조절** — 자연 제안은 보통 1개, 사용자가 세션명 정리를 원하거나 제목 스타일 선택이 유용하면 1~5개 번호 후보를 제시한다.
4. **스팸 금지** — 같은 세션에서 반복 제안하지 않는다.
5. **사용자 언어 유지** — 한국어 대화는 한국어 제목, 영어 대화는 영어 제목.

## 언제 발동하나

### 명시 호출

사용자가 다음처럼 말하면 즉시 실행한다.

- "세션명 바꿔줘"
- "이 대화 제목 정리해줘"
- "세션 이름 추천해줘"
- "rename session"
- "session title"
- "/session-rename"

### 자연 제안

사용자가 명시하지 않아도, 아래 조건이 모두 맞으면 한 번 제안할 수 있다.

- 최근 대화의 실제 주제가 현재 세션명보다 더 구체적이다.
- 대화 주제가 처음 제목과 명확히 달라졌다.
- 현재 제목이 generic 하다. 예: "새 대화", "Untitled", "질문", "작업 정리", 첫 메시지 일부.
- 최근 몇 턴 안에 세션명 제안을 하지 않았다.
- 사용자가 급한 실행·디버깅·문서 작성 흐름에 몰입 중이지 않다.

제안하지 말아야 할 때:

- 사용자가 다른 결정을 기다리고 있다.
- 스트리밍/장기 실행 작업 중이다.
- 세션명이 이미 충분히 구체적이다.
- 같은 세션에서 사용자가 거절했다.
- 제목 변경보다 본 작업 완료가 더 중요하다.

## 제목 작성 규칙

좋은 제목:

- 12–28자 안팎의 한국어 명사구
- 구체적인 산출물·의사결정·주제를 포함
- `Tower`, 고객명, 프로젝트명처럼 찾는 데 중요한 고유명사는 유지
- 사용자가 나중에 검색할 만한 단어를 우선한다

후보 스타일:

| 스타일 | 언제 좋은가 | 예시 |
|---|---|---|
| 핵심 주제형 | 가장 기본. 대화 주제를 빠르게 찾고 싶을 때 | `session-rename UX 설계` |
| 산출물형 | 파일·코드·제안서·스킬처럼 만들어진 것이 있을 때 | `session-rename 스킬 구현` |
| 결정형 | 중요한 합의나 정책 판단이 있었을 때 | `Thin Tool·Thick Skill 결정` |
| 날짜형 | 회의록·운영 작업·일일 점검처럼 시점이 중요할 때 | `2026-06-08 세션명 개선` |
| 요청 반영형 | 사용자가 명시한 핵심 요청을 보존해야 할 때 | `Fleet 공용 스킬 등록 요청` |

피할 제목:

- "작업 정리", "대화 요약", "질문 답변"처럼 너무 넓은 제목
- "좋은 아이디어 논의"처럼 감상적인 제목
- "세션명 자동 업그레이드 스킬 설계 및 구현에 대한 논의"처럼 긴 제목
- 민감 정보, 토큰, 고객 비밀, 개인 연락처

예시:

| 상황 | 후보 |
|---|---|
| 스킬을 설계하고 만들기로 함 | `session-rename 스킬 설계` |
| Tower 배포 정책을 논의함 | `Fleet 배포 가드 정리` |
| 제안서 HTML을 만들고 있음 | `A4 제안서 HTML 제작` |
| 자체 호스팅 서버 스킬 상태를 점검함 | `자체 호스팅 서버 스킬 장부 점검` |

## 제안 문구

자연 제안일 때는 한 문장 + 후보 1개가 기본이다.

> 지금 대화가 **`session-rename 스킬 설계`** 쪽으로 구체화됐습니다. 세션명을 이렇게 바꿔둘까요?

사용자가 명시적으로 "세션명 추천", "제목 정리", "몇 개 골라줘"라고 했거나, 제목의 관점이 여러 개로 갈릴 때는 1~5개 번호 후보를 준다.

> 세션명 후보를 스타일별로 뽑으면 이렇습니다.
>
> 1. **`session-rename UX 설계`** — 핵심 주제형
> 2. **`session-rename 스킬 구현`** — 산출물형
> 3. **`Thin Tool·Thick Skill 결정`** — 결정형
> 4. **`2026-06-08 세션명 개선`** — 날짜형
> 5. **`Fleet 공용 스킬 등록`** — 요청 반영형
>
> 번호로 골라주시면 그 제목으로 바꾸겠습니다.

사용자가 동의하면 변경한다. 애매한 답변("좋네", "그래", "ㅇㅇ")은 직전에 후보가 1개였을 때만 동의로 본다. 후보가 여러 개였으면 번호나 정확한 제목을 받는다. 사용자가 "나중에", "아니", "괜찮아"라고 하면 변경하지 않는다.

## 변경 실행

사용자가 동의하면 현재 AI 런타임의 얇은 세션 제어 도구를 사용한다.

```text
rename_current_session({ title: "<NEW_TITLE>" })
```

이 도구는 현재 세션만 바꿀 수 있다. 다른 세션 ID를 입력받지 않으며, Tower backend가 현재 사용자 권한을 확인한 뒤 `name`, `autoNamed: 0`만 업데이트한다.

중요:

- **사용자 동의 전 호출 금지** — 제안만으로는 도구를 호출하지 않는다.
- **Project Runtime Box(runbox)에서 Tower API를 직접 호출하지 않는다.** runbox는 프로젝트 코드 실행용 컨테이너이며 Tower 본체 제어면이 아니다.
- Credential Vault로 Tower API token을 주입하지 않는다. 세션명 변경은 외부 API secret 문제가 아니라 Tower 내부 capability 문제다.
- 도구가 없거나 실패하면 강행하지 말고 수동 변경을 안내한다.

도구가 없는 환경에서의 fallback:

> 제가 여기서 바로 바꿀 전용 권한은 보이지 않습니다. 사이드바에서 세션명을 클릭해 **`<NEW_TITLE>`** 로 바꾸면 됩니다.

## 응답 형식

### 제안만 했을 때

```text
지금 대화가 **`<NEW_TITLE>`** 쪽으로 구체화됐습니다. 세션명을 이렇게 바꿔둘까요?
```

### 변경 성공

```text
세션명을 **`<NEW_TITLE>`** 로 바꿨습니다.
```

### 변경 실패 / 권한 없음

```text
제목 후보는 **`<NEW_TITLE>`** 입니다. 다만 현재 런타임에서 세션명 변경 권한을 확인하지 못했습니다. 사이드바에서 세션명을 클릭해 같은 제목으로 바꿔주세요.
```

## 경계

- 과거 대화 검색은 `/search`.
- 활성 세션/파일/git 상태 대시보드는 `/wip`.
- 태스크 제목·스케줄 이름 변경은 `/task-schedule`.
- 프로젝트명 변경은 프로젝트 관리 기능이지 이 스킬의 대상이 아니다.

## 실패 모드

- **너무 자주 제안**: 사용자가 거절하거나 무응답이면 같은 세션에서는 한동안 제안하지 않는다.
- **제목이 너무 추상적**: 최근 산출물·결정·기능명을 넣어 다시 줄인다.
- **권한 실패**: API 토큰/세션 접근 권한 문제로 보고하고 수동 변경 안내.
- **다른 세션 오인**: 대상 세션 ID가 불명확하면 바꾸지 말고 확인한다.
