# Pi Skill Loading Policy (Recommendation)

이 문서는 Pi에서 skills를 얼마나 로드할지에 대한 권장 방향을 정리합니다.

## 현재 상태
- `packages/backend/engines/pi-engine.ts`에는 `MAX_PI_SKILLS = 20` 캡이 있습니다.
- 주석상 이유는 prompt bloat 방지입니다.
- 다만 현재 논의 방향은 `AGENTS.md`를 슬림하게 유지하고, 상세 문서는 필요 시 읽게 만드는 것입니다.

## 권장안

### 기본 원칙
- skills 설명 자체는 지나치게 줄이지 않습니다.
- 대신 항상 로드되는 공통 프롬프트(예: `AGENTS.md`)를 짧고 안정적으로 유지합니다.
- 상세 운영 맥락은 참조 문서로 분리합니다.

### MAX_PI_SKILLS에 대한 추천
1. **단기**: 현재 20개 캡을 즉시 더 높이거나 제거하는 것은 가능
2. **중기 권장**: 단순 숫자 캡보다 "활성 스킬만 로드 + 문서 슬림화"가 더 중요
3. **운영 원칙**:
   - active skill 수가 적으면 전부 로드
   - skill 수가 많아도, 각 skill이 짧고 명확하면 허용 가능
   - 정말 길고 무거운 skill은 내부에서 추가 참조 문서 구조로 쪼갭니다.

## 추천 판단
- 지금처럼 공통 문서를 슬림화하는 방향이라면, `20`은 다소 보수적일 수 있습니다.
- 따라서 **고정 20개 캡은 완화 또는 제거 검토 대상**입니다.
- 다만 병목이 skill 설명보다 resource layer일 수 있으므로, 실제 변경 전에는 prompt 크기 로그를 함께 보는 것이 좋습니다.

## 실무적 제안
- 1차: `MAX_PI_SKILLS`를 상향하거나 feature flag로 전환
- 2차: skill별 길이/토큰 측정 로그 추가
- 3차: 과도하게 긴 skill만 분리 리팩토링

## 결론
가장 중요한 것은 "모든 걸 항상 프롬프트에 싣지 않는다"는 구조입니다.
숫자 캡 하나로 해결하기보다:
- 공통 문서는 짧게
- skill은 목적 중심으로 유지
- 상세 맥락은 필요 시 읽기
이 3가지를 기본 정책으로 두는 것을 권장합니다.
