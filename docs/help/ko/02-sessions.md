# 세션 — AI 작업방

세션은 AI와 나누는 **1:1 작업방**입니다. 질문만 하는 곳이 아니라, 분석·작성·코딩·검토·파일 생성까지 이어가는 공간입니다.

---

## 세션을 언제 쓰나요?

| 상황 | 세션이 좋은 이유 |
|---|---|
| 혼자 초안을 만들 때 | 대화 맥락을 길게 유지할 수 있습니다. |
| 파일을 분석할 때 | 첨부와 결과 저장을 한 흐름에서 처리합니다. |
| 코드나 문서를 수정할 때 | AI가 파일을 읽고 수정하고 검증할 수 있습니다. |
| 긴 작업을 이어갈 때 | 한 주제의 판단과 결과가 세션에 남습니다. |

팀 전체가 동시에 봐야 하는 이야기는 채널이 좋고, 집중 작업은 세션이 좋습니다.

---

## 좋은 세션 이름

나중에 찾기 쉽게 세션 이름은 구체적으로 붙이는 것이 좋습니다.

나쁜 예:

- “새 대화”
- “질문”
- “작업”

좋은 예:

- “OKU 7월 매출 PDF 분석”
- “Tower 도움말 한글화”
- “고객 미팅 아젠다 준비”
- “Runtime Box 렌더링 차이 조사”

필요하면 AI에게 “이 세션 이름 추천해줘” 또는 “세션명 바꿔줘”라고 말할 수 있습니다.

---

## 메시지 보내기

| 동작 | 방법 |
|---|---|
| 전송 | Enter |
| 줄바꿈 | Shift + Enter |
| 응답 중단 | Escape |
| 명령어 보기 | `/` 입력 |
| 파일 첨부 | 드래그앤드롭 또는 붙여넣기 |

AI가 응답 중이어도 다음 메시지를 미리 보낼 수 있습니다. 대기열에 들어갔다가 순서대로 처리됩니다.

---

## 파일을 같이 쓰는 법

세션에서 파일을 다룰 때는 세 가지 방식이 있습니다.

### 1. 첨부해서 보여주기

PDF, 이미지, Excel, CSV, 문서 파일을 입력창에 드래그하면 AI가 함께 봅니다.

### 2. 경로를 알려주기

파일 탭에서 경로를 복사해 “이 파일 수정해줘”라고 말하면 정확합니다.

예:

> `~/workspace/projects/acme/work/report.md`를 고객용 문체로 다듬어줘.

### 3. 새 파일로 저장시키기

결과를 채팅에만 두지 말고 파일로 남길 수 있습니다.

예:

> 결과를 `work/summary.md`로 저장하고, 핵심만 채팅에 요약해줘.

---

## Slash command와 스킬

입력창에 `/`를 치면 사용할 수 있는 명령과 스킬이 나타납니다.

스킬은 특정 작업을 위한 전용 모드입니다.

- `/search` — 과거 대화 찾기
- `/issue` — Tower 팀에 이슈 등록
- `/fleet` — 자체 호스팅 서버 운영 작업
- `/task-schedule` — 반복 작업 예약
- `/tower-intro` — Tower 기능 안내

스킬 이름을 몰라도 괜찮습니다. 자연어로 요청하면 AI가 필요한 스킬을 고릅니다.

---

## AI가 물어보는 경우

AI가 항상 바로 실행하는 것이 좋은 것은 아닙니다. 다음 경우에는 먼저 확인할 수 있습니다.

- 대상 독자에 따라 결과가 크게 달라질 때
- 삭제, 배포, 외부 발송처럼 되돌리기 어려울 때
- 프로젝트 정책이나 팀 규칙을 정해야 할 때
- 어떤 파일이 정본인지 불확실할 때

작은 표현 수정이나 쉽게 되돌릴 수 있는 작업은 AI가 가정하고 진행할 수 있습니다.

---

## 서브에이전트로 나눠 맡기기

일이 커지면 AI가 내부적으로 작은 전문 에이전트에게 일부 검토를 맡길 수 있습니다. 사용자는 보통 “여러 관점으로 나눠서 봐줘”라고 말하면 됩니다.

어울리는 상황:

- 코드 수정 후 별도 리뷰어에게 회귀 위험을 점검시키기
- 제안서를 “고객 관점”과 “운영 리스크 관점”으로 나눠 검토하기
- 긴 자료를 파트별로 읽고 마지막에 결론만 합치기
- 디자인, 보안, 성능처럼 서로 다른 기준을 병렬로 확인하기

요청 예시:

> 이 기능 변경안을 구현 관점, UX 관점, 운영 리스크 관점으로 나눠 검토하고 마지막에 하나의 결론으로 합쳐줘.

서브에이전트는 일을 빠르게 나누는 도구이지만, 최종 판단과 사용자에게 보고하는 책임은 현재 세션의 AI가 집니다.

---

## 세션에서 많이 하는 작업

### 문서 작업

> 이 초안을 고객 제안서 톤으로 고쳐줘. 너무 과장하지 말고 근거 중심으로.

### 분석 작업

> 이 PDF를 보고 핵심 주장, 숫자, 리스크, 추가 질문을 정리해줘.

### 코드 작업

> 이 오류의 원인을 찾아서 최소 수정으로 고쳐줘. 관련 테스트도 실행해줘.

### 인계 작업

> 지금까지 한 일을 다음 세션이 이어받게 인계 문서로 정리해줘.

---

## 세션과 커밋

Tower 코드베이스 같은 개발 프로젝트에서는 AI가 파일을 수정한 뒤 커밋까지 만들 수 있습니다.

다만 원칙이 있습니다.

- 사용자가 명시적으로 요청할 때만 커밋합니다.
- 다른 세션이 만든 변경은 함부로 커밋하지 않습니다.
- 현재 세션이 수정한 파일만 stage합니다.
- 커밋 메시지에는 Tower 세션 추적 정보가 들어갑니다.

이 원칙은 여러 사람이 같은 서버에서 일할 때 서로의 작업을 보호하기 위한 것입니다.

---

## 좋은 요청 예시

> 이 세션에서는 Tower 도움말 메뉴를 초보자용 한국어로 바꾸고 싶어. 최근 기능인 스킬, 게시, 스케줄, 파일 산출물 규칙까지 담아줘. 수정 후 빌드 확인하고 현재 세션 변경만 커밋해줘.

이렇게 말하면 목적, 범위, 검증, 마무리 기준이 모두 들어 있어 AI가 덜 헤맵니다.
