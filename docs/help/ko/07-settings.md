# 설정·권한·Connection

Tower는 개인 설정, 프로젝트 권한, 서버 관리와 외부 계정 연결을 서로 다른 경계로 관리합니다.

## 내 설정

**내 설정**에서는 다음과 같은 개인 옵션을 관리합니다.

- 프로필과 비밀번호
- 언어
- 밝은 화면과 어두운 화면
- 글자 크기
- 알림 표시 위치와 알림 그룹
- 서버가 제공하는 개인 옵션. 개인 로그인은 Agent 실행에 자동 상속되지 않습니다.

개인 설정은 현재 사용자 계정에 속합니다. 다른 멤버의 설정이나 프로젝트 권한을 자동으로 바꾸지 않습니다.

## 프로젝트 권한

프로젝트는 파일, 세션, 멤버와 AI 팀원의 권한 경계입니다.

역할과 서버 설정에 따라 다음 항목을 관리할 수 있습니다.

- 프로젝트에 접근할 수 있는 사용자
- 멤버 역할
- Primary AI 팀원의 프로필
- 도구와 권한 정책
- 사용할 수 있는 스킬
- AI 팀원이 사용할 Agent 전용·회사 공용 Connection

어떤 협업 공간에 Agent를 초대했다고 해서 다른 프로젝트의 파일이나 Credential 권한이 자동으로 생기지는 않습니다.

## Connection과 Credential

**Connection**은 승인된 외부 서비스 계정과 사용 정책을 의미합니다. 실제 API key, OAuth token, password 또는 Credential 문서는 Credential Vault에 저장됩니다.

Secret 값은 대화에 붙여 넣거나 프로젝트 파일에 커밋하지 않습니다.

Connection 준비 상태는 세 단계로 구분합니다.

1. 현재 사용자 또는 프로젝트에 허용된 Connection이 설정되어 있는가
2. 해당 실행의 Runtime command에 Credential이 안전하게 주입되었는가
3. 외부 Provider가 인증을 받아들였는가

서비스가 실패하면 어느 단계에서 실패했는지와 다음 조치를 확인합니다. Provider 인증 오류만으로 Connection이 삭제됐다고 단정하지 않습니다.

## Agent 전용 연결과 회사 공용 연결

Agent 전용(project) 연결은 해당 Agent의 업무 자원입니다. 요청자의 개인 로그인은 암묵적으로 상속하지 않습니다. 개인 계정을 공유 Agent에 연결하기 전에는 그 Agent의 이용자가 해당 계정으로 업무를 요청해도 되는지 확인합니다.

회사 공용(workspace) 연결은 회사 관리자가 준비하며 일반 프로젝트에 자동 제공됩니다. 특정 Agent에만 연결하려면 Agent 전용 범위를 사용합니다. 기존 개인 연결은 소유자 동의 없이 공용으로 자동 전환하지 않습니다.

Google 연결의 선택 순서, 오류 대응, 관리자 참여 및 전환 체크리스트는 [Agent 권한과 연결 운영 매뉴얼](./09-agent-authority-connections.md)을 참고하십시오.

Connection을 끊으면 이후 사용이 즉시 중단될 수 있습니다. 서버 정책에 따라 복구를 위한 metadata나 접근 정책은 보존될 수 있습니다.

## 모델과 AI 정책

관리자는 사용 가능한 Provider·모델과 주요 업무, 짧은 보조 업무, 백그라운드 실행에 사용할 기본 모델 정책을 설정할 수 있습니다.

Tower는 편집 가능한 하나의 raw System Prompt를 AI 행동의 유일한 정본으로 사용하지 않습니다. 제품 정책, 조직 설정, 프로젝트 `AGENTS.md`, Runtime context, 스킬과 권한 정책을 함께 적용합니다.

## 알림

알림 설정에서는 다음 항목을 조절할 수 있습니다.

- 알림 센터 기록
- 앱 안의 일시적 알림
- 브라우저 또는 PWA push
- 멘션과 직접 요청
- 긴 작업 완료
- 조치가 필요한 실패
- 일반 AI·업무 업데이트

브라우저 push는 브라우저 권한과 서버 설정이 모두 필요합니다.

## 관리자·운영자 작업

Operator는 회사 Agent·업무·공용 연결을 관리하는 회사 관리자이며 플랫폼 관리자가 아닙니다. 타인의 개인 비공개 대화 열람, admin/operator 승격, 타인 비밀번호 직접 재설정이나 임의 호스트 접근 권한은 자동으로 생기지 않습니다.

Admin은 플랫폼·인프라를 관리합니다. 배포·재시작·시스템 설정은 별도 플랫폼 권한과 확인이 필요합니다. admin이 요청하더라도 일반 Agent의 실행 권한이 확대되지는 않습니다.

화면에 버튼이나 파일 경로가 보인다는 사실만으로 실행 권한이 생기지는 않습니다. Tower backend가 현재 사용자와 작업 권한을 검증합니다.
