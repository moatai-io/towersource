# 파일 — 산출물과 자료

Tower에서 파일은 단순 첨부물이 아닙니다. AI가 읽고, 고치고, 새로 만들고, 사용자가 다시 열어보는 **공동 작업의 결과물**입니다.

---

## 파일 탭에서 할 수 있는 일

왼쪽의 **Files** 탭을 열면 프로젝트 파일을 볼 수 있습니다.

| 할 일 | 방법 |
|---|---|
| 파일 열기 | 파일명 클릭 |
| 폴더 펼치기 | 폴더 클릭 |
| 새 파일/폴더 | 우클릭 메뉴 |
| 이름 변경 | 우클릭 후 Rename |
| 삭제 | 우클릭 후 Delete, 확인 필요 |
| 경로 복사 | 우클릭 후 Copy path |
| 다운로드/공유 | 우클릭 메뉴 또는 패널 버튼 |

파일을 클릭하면 보통 오른쪽 패널에서 미리보기나 편집기가 열립니다.

---

## 파일은 어디에 두나요?

프로젝트에 정해진 구조가 있으면 그 규칙을 따릅니다. 일반적으로는 아래 기준을 씁니다.

| 폴더 | 넣는 것 |
|---|---|
| `sources/` | 원본 자료, 업로드 파일, 캡처, 회의록 원문 |
| `work/` | 초안, 중간 분석, 실험 결과 |
| `final/` | 공유 가능한 최종 산출물 |
| `records/` | 실행 기록, 로그, 검증 근거 |
| `knowledge/` | 다음에도 쓸 절차, 패턴, 요약 지식 |
| `.project/decisions/` | 프로젝트의 중요한 결정 |

AI에게 저장 위치를 말하지 않으면, AI가 프로젝트 규칙을 보고 적절한 곳을 고릅니다.

---

## 경로가 중요한 이유

Tower에서는 사용자가 열어볼 파일을 만들거나 수정하면, AI가 응답에 파일 경로를 알려줘야 합니다.

예:

`~/workspace/projects/my-project/work/summary.md`

이 경로는 클릭해서 파일 탭에서 바로 열 수 있습니다.

상대경로만 쓰면 찾기 어려울 수 있으니, 최종 안내에는 보통 `~/workspace/...` 형태가 좋습니다.

---

## 파일 미리보기와 편집

| 파일 종류 | Tower에서 보는 방식 |
|---|---|
| Markdown | 읽기 좋은 문서 미리보기와 편집 |
| 코드 | 구문 강조 편집기 |
| PDF | 페이지 미리보기, 필요 시 시각 분석 |
| 이미지 | 이미지 미리보기 |
| Excel/CSV | 분석 도구로 구조 파악 가능 |
| HTML | 파일로 열거나 게시 가능 |

Markdown은 Tower에서 특히 자주 씁니다. 보고서, 인계, 결정문서, 체크리스트를 남기기 좋습니다.

---

## AI에게 파일 작업을 맡기는 법

### 특정 파일 읽기

> `~/workspace/projects/acme/sources/meeting.md` 읽고 결정사항만 정리해줘.

### 파일 수정

> `work/proposal.md`의 도입부를 고객용으로 더 쉽게 고쳐줘. 나머지 구조는 유지해줘.

### 새 파일 만들기

> 분석 결과를 `work/customer-risk-summary.md`로 저장해줘.

### 여러 파일 비교

> `sources/2025.csv`와 `sources/2026.csv`를 비교해서 변화가 큰 항목을 Excel로 만들어줘.

---

## 업로드와 첨부의 차이

| 방식 | 뜻 |
|---|---|
| 파일 탭에 업로드 | 프로젝트 자료로 저장됩니다. 나중에 다시 찾기 좋습니다. |
| 채팅 입력창에 첨부 | 이번 대화에서 AI에게 보여줍니다. |

중요 자료는 파일 탭에 남겨두는 것이 좋습니다.

---

## 공유와 게시의 차이

| 기능 | 언제 쓰나요? |
|---|---|
| 파일 공유 | 특정 파일을 링크로 보여줄 때 |
| 게시(Publish) | HTML 사이트나 대시보드를 외부 URL로 열게 할 때 |
| PDF/DOCX 생성 | 문서 형태로 전달할 때 |

웹페이지나 대시보드는 그냥 로컬 주소를 알려주는 것이 아니라 Tower의 게시 기능을 통해 공유해야 합니다.

---

## 조심해야 할 파일

- `.env` 같은 비밀 설정 파일은 내용을 출력하지 않습니다.
- 다른 사용자가 작업 중인 파일은 함부로 덮어쓰지 않는 것이 좋습니다.
- 삭제, 대량 이동, 배포 파일 변경은 확인 후 진행합니다.
- 프로젝트 밖 임시 폴더에 최종 산출물을 두지 않습니다.

---

## 파일 작업 팁

- AI에게 “수정 전 어떤 파일을 바꿀지 먼저 알려줘”라고 할 수 있습니다.
- “현재 세션이 만든 파일만 커밋해줘”라고 하면 다른 사람 변경을 보호할 수 있습니다.
- 최종본은 `final/`, 초안은 `work/`에 두면 팀원이 찾기 쉽습니다.
- 중요한 이유나 정책은 채팅보다 문서로 남기는 것이 좋습니다.
