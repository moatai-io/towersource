# 단축키와 좋은 요청법

Tower를 잘 쓰는 핵심은 단축키보다 **요청을 잘 쓰는 법**입니다. 그래도 기본 조작을 익히면 훨씬 빨라집니다.

---

## 기본 단축키

| 단축키/동작 | 의미 |
|---|---|
| Enter | 메시지 전송 |
| Shift + Enter | 줄바꿈 |
| Escape | 응답 중단 또는 대기 메시지 취소 |
| `/` | 사용 가능한 명령어/스킬 보기 |
| Ctrl/Cmd + V | 이미지나 캡처 붙여넣기 |
| 파일 드래그 | 입력창에 첨부 또는 파일 탭에 업로드 |
| 우클릭 | 파일/세션 메뉴 열기 |

---

## 가장 좋은 요청 구조

AI에게 일을 맡길 때는 아래 순서가 좋습니다.

1. **무엇을 원하는지** — 보고서, 분석, 수정, 요약, 코드 변경
2. **누가 볼 것인지** — 고객, 임원, 개발자, 내부 팀
3. **어떤 형식인지** — 채팅 요약, Markdown, PDF, Excel, HTML, PPTX
4. **무엇을 조심할지** — 추정 금지, 숫자 근거 표시, 파일 덮어쓰기 금지
5. **어디에 저장할지** — `work/`, `final/`, 특정 파일 경로

예:

> 이 PDF를 고객 미팅 준비용으로 요약해줘. 핵심 주장, 근거 숫자, 반박 가능성, 질문 리스트로 나눠줘. 결과는 `work/meeting-brief.md`에 저장해줘.

## 상황별 요청 예시

### 문서 작성

> 이 메모를 바탕으로 비개발 임원용 1페이지 보고서를 만들어줘. 결론을 먼저 쓰고, 근거는 3개만 남겨줘.

### 파일 분석

> 첨부한 엑셀의 시트 구조와 수식 의도를 먼저 설명하고, 이상치가 있는 행을 찾아줘.

### 코드 수정

> 이 오류를 재현할 수 있는 테스트를 먼저 찾고, 최소 변경으로 고쳐줘. 현재 세션이 수정한 파일만 알려줘.

### PDF 생성

> 이 Markdown을 A4 PDF로 만들어줘. 표가 페이지 밖으로 넘치지 않는지 검증해줘.

### 웹 게시

> 이 HTML 대시보드를 unlisted 링크로 게시해줘. 성공한 URL만 알려줘.

### 스케줄

> 매주 월요일 오전 9시에 이 프로젝트의 지난주 진행상황을 요약해줘. 결과는 현재 세션에 남겨줘.

## AI가 헷갈리지 않게 하는 말

| 이렇게 말하면 좋음 | 이유 |
|---|---|
| “먼저 수정 대상 파일을 찾아줘” | 엉뚱한 파일 변경을 줄입니다. |
| “초안은 `work/`, 최종본은 `final/`에 둬” | 산출물 위치가 명확합니다. |
| “확실하지 않으면 추정이라고 표시해” | 사실과 해석이 섞이지 않습니다. |
| “중요한 결정은 문서로 남겨줘” | 팀이 나중에 이유를 알 수 있습니다. |
| “현재 세션 변경만 커밋해줘” | 다른 사람 작업이 섞이지 않습니다. |
| “삭제/배포 전에는 확인해줘” | 되돌리기 어려운 실수를 막습니다. |

## 결과가 별로일 때 고치는 법

AI 답변이 마음에 안 들면 처음부터 다시 시키기보다, 어느 부분이 문제인지 말해주는 것이 좋습니다.

| 문제 | 다시 요청하는 법 |
|---|---|
| 너무 길다 | “절반 길이로 줄이고 결론만 남겨줘.” |
| 너무 어렵다 | “비개발자도 이해하게 쉬운 비유를 넣어줘.” |
| 근거가 약하다 | “주장마다 근거 파일/숫자를 붙여줘.” |
| 디자인이 밋밋하다 | “더 고급스럽게, 단 정보 밀도는 유지해줘.” |
| 표가 복잡하다 | “의사결정에 필요한 컬럼만 남겨줘.” |
| 파일이 어디 있는지 모르겠다 | “생성/수정한 파일 경로만 다시 알려줘.” |

### 의사결정

> 선택지 3개를 장단점, 리스크, 추천 기준으로 비교해줘. 결정하면 문서로 남길 위치도 제안해줘.
