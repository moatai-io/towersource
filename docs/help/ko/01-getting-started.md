# 처음 시작하기

Tower를 처음 열면 기능이 많아 보일 수 있습니다. 하지만 기본 흐름은 단순합니다.

> **프로젝트 선택 → 세션에서 AI에게 요청 → 파일 탭에서 결과 확인 → 필요하면 공유**

이 문서는 처음 10분 동안 알아야 할 것만 쉽게 설명합니다.

---

## 1. 프로젝트부터 확인하기

Tower의 모든 작업은 대체로 **프로젝트** 안에서 움직입니다.

프로젝트는 폴더이자 작업 맥락입니다.

- 관련 세션을 묶습니다.
- 관련 파일을 한곳에 둡니다.
- AI에게 프로젝트 규칙을 알려줍니다.
- 팀원 권한의 기준이 됩니다.

프로젝트 안에는 보통 이런 파일과 폴더가 있습니다.

| 위치 | 뜻 |
|---|---|
| `AGENTS.md` | 이 프로젝트에서 AI가 따라야 할 규칙 |
| `sources/` | 원본 자료, 업로드, 캡처 |
| `work/` | 초안, 중간 산출물 |
| `final/` | 공유 가능한 최종본 |
| `records/` | 실행 기록, 로그, 근거 |
| `knowledge/` | 반복해서 쓸 지식과 절차 |

프로젝트마다 구조가 다를 수 있으니, AI는 먼저 프로젝트 지침을 확인하고 움직입니다.

---

## 2. 세션 만들기

**세션**은 AI와 나누는 1:1 작업방입니다.

1. 왼쪽에서 **Sessions**를 엽니다.
2. **+** 버튼을 누릅니다.
3. 새 대화가 열리면 원하는 일을 입력합니다.

세션은 주제별로 나누는 것이 좋습니다.

- “7월 제안서 작성”
- “자체 호스팅 서버 배포 점검”
- “엑셀 매출 분석”
- “디자인 시안 만들기”

한 세션에 너무 많은 주제를 섞으면 AI도 맥락을 헷갈릴 수 있습니다.

---

## 3. 첫 요청은 이렇게 하기

AI에게 일을 맡길 때는 아래 네 가지가 있으면 결과가 좋아집니다.

| 넣으면 좋은 것 | 예시 |
|---|---|
| 목적 | “임원 보고용으로” |
| 대상 | “비개발자도 이해하게” |
| 형식 | “1페이지 Markdown으로” |
| 기준 | “추정은 추정이라고 표시” |

예시:

> 이 회의 메모를 바탕으로 고객에게 보낼 후속 메일 초안을 만들어줘. 정중하지만 길지 않게, 결정사항과 요청사항을 구분해줘.

예시:

> 이 엑셀을 분석해서 매출 변화, 이상치, 다음 질문을 정리해줘. 결과는 Markdown 리포트와 요약 Excel로 만들어줘.

---

## 4. 파일을 첨부하거나 열기

Tower에서는 파일을 AI에게 바로 줄 수 있습니다.

| 방법 | 언제 쓰나요? |
|---|---|
| 입력창에 드래그 | PDF, 이미지, 엑셀을 분석시킬 때 |
| 파일 탭에서 클릭 | 프로젝트 파일을 직접 열 때 |
| 파일 경로 붙여넣기 | AI에게 특정 파일 수정을 요청할 때 |
| 스크린샷 붙여넣기 | 화면 문제를 보여줄 때 |

AI가 파일을 만들거나 수정하면, 보통 응답에 경로를 알려줍니다. 그 경로를 클릭하면 파일 탭에서 바로 열립니다.

---

## 5. 결과물을 어디에 저장하나?

Tower에서는 사람이 다시 열어볼 산출물을 프로젝트 밖 임시 폴더에 두지 않는 것이 원칙입니다.

일반적인 기준은 다음과 같습니다.

| 산출물 종류 | 추천 위치 |
|---|---|
| 원본 자료 | `sources/` |
| 초안/작업 중 파일 | `work/` |
| 최종 보고서/PDF/HTML | `final/` |
| 실행 로그/근거 | `records/` |
| 재사용 절차 | `knowledge/` |

사용자가 “저장해줘”라고 하면 AI는 프로젝트 안에 저장하고, 열 수 있는 경로를 알려줘야 합니다.

---

## 6. AI가 할 수 있는 일

Tower의 AI는 단순 답변만 하지 않습니다.

- 문서 작성과 요약
- 코드 읽기, 수정, 테스트
- Excel/CSV 분석
- PDF 시각 검토와 표 추출
- HTML/PDF/DOCX/슬라이드 제작
- 정적 사이트 게시
- 과거 대화 검색
- 스케줄 등록
- Git 커밋/PR 준비
- 자체 호스팅 서버 운영 점검

단, 삭제·배포·외부 발송처럼 되돌리기 어려운 일은 확인을 거칩니다.

---

## 7. 스킬은 무엇인가요?

**스킬**은 특정 일을 더 잘하기 위한 전용 작업법입니다.

예를 들어:

| 스킬 예 | 쓰는 상황 |
|---|---|
| PDF/HTML/PPT 관련 스킬 | 발표자료, 보고서, PDF 변환 |
| Google Workspace 스킬 | Gmail, Calendar, Drive, Sheets 작업 |
| 검색 스킬 | 네이버, 유튜브, 과거 대화 검색 |
| Fleet 스킬 | 고객 Tower VM 점검과 배포 |
| Issue 스킬 | Tower 팀에 버그/개선 요청 등록 |

사용자가 꼭 스킬 이름을 몰라도 됩니다. “유튜브 대본 요약해줘”, “PPT 만들어줘”처럼 말하면 AI가 맞는 절차를 고릅니다.

---

## 8. 처음에 자주 하는 실수

### 실수 1. 파일 위치를 안 정함

“보고서 만들어줘”보다 “프로젝트 `work/` 아래에 Markdown으로 저장해줘”가 좋습니다.

### 실수 2. 대상 독자를 안 말함

임원용, 고객용, 개발자용, 내부 공유용은 글의 깊이와 표현이 달라집니다.

### 실수 3. 한 번에 너무 큰 일을 맡김

“서비스 전체 개선”보다 “첫 화면의 가입 흐름을 분석하고 개선안 3개를 제시”가 좋습니다.

### 실수 4. 중요한 결정을 채팅에만 둠

계속 유지할 정책이나 합의는 결정문서나 프로젝트 문서로 남기는 것이 좋습니다.
