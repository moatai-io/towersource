# 시각화와 산출물

Tower는 구조화된 결과를 세션 안에서 바로 보여주고, 다시 열거나 편집·인쇄·공유해야 하는 결과는 프로젝트 파일로 만들 수 있습니다.

## 목적에 맞는 형식 선택

| 필요 | 권장 형식 |
|---|---|
| 프로세스·아키텍처·관계 | Mermaid 다이어그램 |
| 숫자 비교 | 차트 또는 데이터 테이블 |
| 시간에 따른 추세 | 선·영역 차트 |
| 밀도 높은 구조화 데이터 | 데이터 테이블 또는 Excel |
| 변경 전후 비교 | Diff 또는 Comparison |
| 순서가 있는 활동 기록 | Timeline |
| 명령 실행 근거 | Terminal 블록 |
| 인터랙티브한 정적 결과 | HTML 산출물 |
| 인쇄용 보고서 | PDF |
| 편집 가능한 업무 문서 | DOCX |
| 재사용할 분석·원본 | Markdown, CSV, JSON 또는 프로젝트 파일 |

## 세션 안의 시각 블록

Tower가 표현할 수 있는 구조화 블록에는 다음이 있습니다.

- Mermaid 다이어그램
- 차트와 treemap
- 데이터 테이블
- timeline과 진행 단계
- 지도
- diff와 comparison
- 이미지 gallery
- terminal 출력
- 인터랙티브 form
- HTML과 SVG preview
- CAD evidence preview

시각화는 장식이 아니라 관계, 순서, 크기 또는 판단을 일반 문장보다 쉽게 이해하게 할 때 사용합니다.

## Viewer Pane과 파일

다시 사용할 산출물은 프로젝트에 파일로 저장하고 Viewer Pane에서 엽니다. Viewer Pane에서는 세션 맥락을 유지한 채 지원되는 파일을 확인하거나 편집할 수 있습니다.

다음 경우 프로젝트 파일로 남기는 것이 좋습니다.

- 다른 팀원이 나중에 검토해야 할 때
- 여러 세션에 걸쳐 수정할 때
- 안정적인 파일 경로가 필요할 때
- 다른 프로젝트로 전달하거나 대화에 첨부할 때
- 게시 또는 최종 형식으로 export할 때

## PDF·스프레드시트·CAD 분석

레이아웃이 중요한 형식은 시각 검토가 필요합니다.

- PDF는 추출 텍스트만 보지 않고 렌더링된 페이지를 확인합니다.
- 스프레드시트는 수식, 병합 헤더, 숫자 형식과 의미 있는 서식을 보존해 읽습니다.
- CAD preview는 시각적 이해에 유용하지만 중요한 치수·공차의 공학적 승인 근거를 대신하지 않습니다.

Tower는 이런 작업을 위해 전용 Runtime Guide를 사용합니다.

## 정적 결과 게시

정적 HTML 사이트나 보고서는 Tower Publishing Hub를 통해 게시할 수 있습니다.

1. 프로젝트 안에 `index.html`이 있는 출력 폴더를 만듭니다.
2. 게시 전에 결과를 검토합니다.
3. 기본 공개 범위는 **unlisted**를 사용합니다.
4. 검색 가능한 공개 URL이 필요하다고 명시한 경우에만 **public**을 사용합니다.
5. 게시가 성공한 뒤 반환된 URL만 공유합니다.

서버 게시 폴더에 직접 파일을 쓰거나 성공하지 않은 URL을 추측해서 안내하지 않습니다.

## PDF export

최종 PDF가 필요하면 Tower는 print-ready HTML을 PDF pipeline으로 내보내고 렌더링된 페이지를 다시 확인합니다.

원본 빌드가 성공한 것만으로는 충분하지 않습니다. 최종 PDF에서 페이지 나눔, 폰트, 다이어그램, 차트와 잘린 내용을 확인합니다.

## 산출물 경로

사용자-facing 파일은 현재 프로젝트 안에 둡니다. 일반적인 관례는 다음과 같습니다.

```text
work/      중간 작업
final/     공유 가능한 최종 결과
sources/   원본 자료
records/   장기 기록
```

현재 프로젝트의 `AGENTS.md`가 다른 경로를 정하면 그 지침을 따릅니다.
