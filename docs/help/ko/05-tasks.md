# 작업·스케줄

Tower에서는 AI에게 지금 바로 일을 맡길 수도 있고, 나중에 또는 반복적으로 실행되게 예약할 수도 있습니다.

쉽게 말해:

- **작업**은 “AI에게 맡긴 일”
- **스케줄**은 “정해진 시간에 AI가 다시 하게 하는 일”입니다.

---

## 언제 작업으로 맡기나요?

| 상황 | 예시 |
|---|---|
| 시간이 걸리는 분석 | “이 폴더의 문서를 모두 읽고 요약해줘” |
| 파일 생성/수정 | “보고서 초안을 만들고 `work/`에 저장해줘” |
| 코드 작업 | “이 버그를 고치고 테스트를 돌려줘” |
| 검토 작업 | “이 제안서의 리스크를 찾아줘” |

짧은 질문은 그냥 세션에서 물어보면 됩니다. 파일을 만들거나 실제 변경이 생기는 일은 작업 단위로 추적하는 것이 좋습니다.

---

## 스케줄은 언제 쓰나요?

반복되거나 미래에 실행할 일이 있을 때 씁니다.

| 요청 | 스케줄 예시 |
|---|---|
| 매일 요약 | 매일 오전 9시 어제 대화 요약 |
| 주간 점검 | 매주 월요일 프로젝트 리스크 정리 |
| 리마인더 | 내일 오후 3시에 자료 검토 알림 |
| 정기 보고 | 매주 금요일 진행상황 보고서 작성 |

스케줄은 최소 1분, 최대 1주 간격 범위에서 다루는 것이 기본입니다.

---

## 자동화와 스킬은 언제 쓰나요?

스케줄이 “언제 다시 실행할지”를 정한다면, 스킬은 “어떤 순서와 기준으로 실행할지”를 정합니다.

예를 들어 한 번 해본 보고서 제작 과정이 다음과 같았다고 해보세요.

1. 원본 PDF와 Excel을 읽는다.
2. 숫자 근거를 먼저 검증한다.
3. 임원용 결론 3개로 줄인다.
4. 리스크와 미결 질문을 분리한다.
5. Markdown, PDF, HTML 게시본을 만든다.

이런 과정은 말로만 다시 설명하면 매번 조금씩 달라집니다. 스킬로 만들면 **복잡한 순서, 미묘한 톤, 검증 기준, 저장 위치**를 다음에도 거의 같은 방식으로 재현할 수 있습니다.

요청 예시:

> 이 회의록 정리 방식이 마음에 들어. 다음에도 같은 순서로 하게 스킬 후보로 정리해줘.

> 매주 금요일에 이 스킬을 써서 주간 리포트를 만들도록 자동화할 수 있을지 봐줘.

---

## 스케줄 등록 흐름

AI는 스케줄을 바로 몰래 만들지 않습니다. 보통 이렇게 진행합니다.

1. 사용자가 “매일 9시에 요약해줘”처럼 요청합니다.
2. AI가 시간대, 반복 주기, 실행할 프롬프트, 결과를 남길 곳을 정리합니다.
3. 사용자가 확인합니다.
4. AI가 Tower 스케줄에 등록합니다.

예시:

> 매주 월요일 오전 9시에 이 프로젝트의 지난주 완료 작업과 남은 리스크를 요약해줘. 결과는 현재 세션에 남겨줘.

---

## 좋은 작업 요청법

좋은 작업은 결과 기준이 분명합니다.

나쁜 예:

> 알아서 정리해줘.

좋은 예:

> `sources/`의 회의록 3개를 읽고, 결정사항/담당자/마감일/미결 질문으로 나눠 `work/meeting-actions.md`에 정리해줘.

더 좋은 예:

> 담당자가 명확하지 않은 항목은 “담당자 미정”으로 표시하고, 추정하지 마.

---

## 진행상태를 보는 법

작업형 요청에서는 AI가 보통 현재 진행 단계를 보여줍니다.

- 무엇을 확인 중인지
- 어떤 산출물을 만들고 있는지
- 검증이 끝났는지
- 막힌 점이 있는지
- 최종 파일이 어디 있는지

Tower에서는 작업 진행을 Todo나 Process Map 형태로 보여줄 수 있습니다. 사용자는 세부 명령을 몰라도 “지금 어느 단계인가”를 알 수 있습니다.

---

## 반복 작업에 어울리는 예시

### 매일 브리핑

> 매일 오전 8시 30분에 오늘 확인해야 할 일정, 미해결 작업, 최근 이슈를 짧게 정리해줘.

### 주간 회고

> 매주 금요일 오후 5시에 이번 주 완료한 일, 막힌 일, 다음 주 첫 액션을 정리해줘.

### 자료 점검

> 매일 오전 10시에 `sources/`에 새 파일이 있으면 요약하고, 없으면 “새 자료 없음”이라고 남겨줘.

---

## 작업·스케줄에서 조심할 점

- 외부로 메일을 보내거나 배포하는 일은 확인 없이 실행하지 않습니다.
- 삭제나 대량 변경은 먼저 확인합니다.
- 스케줄이 너무 자주 돌면 비용과 알림 소음이 생길 수 있습니다.
- 반복 작업의 결과를 어디에 남길지 미리 정하는 것이 좋습니다.

---

## 초보자 팁

- “매일/매주/내일/반복” 같은 말이 들어가면 스케줄이라고 보면 됩니다.
- “파일 만들어줘/수정해줘/검증해줘”는 작업입니다.
- 스케줄을 만들 때는 시간대와 결과 위치를 꼭 확인하세요.
- 중요한 자동화는 처음 한두 번 결과를 직접 확인하세요.
