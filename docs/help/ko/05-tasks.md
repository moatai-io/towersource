# 내 작업과 자동화

Tower는 **업무 진행 상황**과 **예약 실행**을 구분합니다.

- **내 작업**에서는 진행 중인 workstream, 단계, 결과, 결정, 열린 질문, 관련 대화와 승인 요청을 확인합니다.
- **자동화**에서는 언제 무엇을 확인하거나 실행할지, AI가 언제 개입하고 결과를 어디에 남길지 정합니다.

## 내 작업

메인 메뉴에서 **내 작업**을 열면 여러 프로젝트에서 이어지는 업무를 한곳에서 볼 수 있습니다.

하나의 workstream에는 다음 정보가 포함될 수 있습니다.

- 현재 단계와 완료된 단계
- 최근 실행과 결과
- 결정사항과 해결되지 않은 질문
- 관련 세션
- 다음 후보와 backlog
- 사람의 확인이 필요한 승인 요청

내 작업은 진행 상황과 연속성을 보여주는 화면입니다. 실제 업무가 수행된 전체 대화는 관련 세션에서 확인하고 이어갑니다.

## 진행 단계

긴 작업에서는 AI가 현재 진행 단계를 표시할 수 있습니다. 사용자는 어떤 단계가 실행 중인지, 어디에서 문제가 생겼는지 확인할 수 있습니다.

진행 단계는 사용자의 개인 할 일 목록이 아닙니다. AI 실행의 진행 상황을 설명합니다. 개인 메모와 개인 할 일은 별도의 사용자 전용 공간에 저장됩니다.

## 자동화

**자동화** 화면에서는 다음 상태를 확인할 수 있습니다.

- 현재 활성화된 자동화
- 예정된 실행
- 지금 실행 중인 작업
- 확인이 필요한 실패
- 최근 등록하거나 수정한 자동화

자동화는 일반적으로 다음을 정의합니다.

- 이름과 목적
- 실행할 프로젝트
- 실행할 프롬프트 또는 점검
- 수동, 1회, 매일, 평일, 매주 또는 반복 간격
- 결과를 남길 위치
- 항상 AI를 실행할지, 조건이 충족될 때만 실행할지

## AI와 자동화 만들기

권장 흐름은 대화형 설정입니다.

1. **자동화 만들기**를 선택하거나 프로젝트 세션에서 반복 작업을 요청합니다.
2. 무엇을, 왜, 언제 실행하고 결과를 어디에 남길지 설명합니다.
3. Tower가 빠진 조건을 질문합니다.
4. 최종 요약을 검토합니다.
5. 내용을 확인한 뒤 등록을 승인합니다.

예시:

> 매주 평일 오전 9시에 이 프로젝트의 어제 완료 업무와 오늘의 위험 요소를 요약하고 새 실행 세션에 남겨줘.

## 자동화 수정

자동화 전용 대화에서 자연어로 변경을 요청할 수 있습니다. Tower는 변경 내용, 위험, 경고와 영향을 담은 검토안을 만들 수 있습니다.

검토안이 만들어졌다는 사실만으로 변경이 적용되지는 않습니다. 정확한 변경안을 확인한 뒤 승인해야 합니다.

## 실행 기록과 실패

다음 항목을 구분해서 확인합니다.

- 마지막 실행과 다음 실행
- 현재 진행 단계
- 완료·실패한 단계
- 점검은 실행됐지만 AI 개입이 필요하지 않았는지
- 결과 세션 또는 저장 위치
- 사용자나 운영자의 조치가 필요한 경고

Provider 인증 실패, Connection 누락, Runtime 실패, 잘못된 스케줄은 서로 다른 문제입니다. 모든 실패를 모델 문제로 간주하지 말고 표시된 상태와 다음 조치를 확인합니다.

## 안전 원칙

- 자동화는 정해진 프로젝트와 소유자 권한으로 실행됩니다.
- 스케줄 등록이 새로운 파일·도구·Credential 권한을 부여하지 않습니다.
- 외부 쓰기나 파괴적 작업에는 별도 승인이 필요할 수 있습니다.
- 반복 실행이 피해를 만들 수 있다면 환경을 바꾸기 전에 자동화를 비활성화합니다.
- 실행 이력을 보존해야 한다면 완전 삭제보다 보관을 우선합니다.
