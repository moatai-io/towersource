# Tower 한눈에 보기

Tower는 **팀이 AI와 함께 일하는 작업실**입니다. 그냥 챗봇 하나를 띄우는 곳이 아니라, 대화·파일·문서·자동화·웹 게시·스케줄·팀 기록을 한 프로젝트 안에서 이어 붙여 줍니다.

처음 보는 분은 이렇게 기억하면 됩니다.

> **프로젝트를 고르고 → AI에게 일을 맡기고 → 파일과 결과물을 확인하고 → 필요하면 팀과 공유합니다.**

## 30초 요약

| 궁금한 것 | 어디서 하나요? | 한 줄 설명 |
|---|---|---|
| AI와 개인 대화 | **세션** | 주제별 1:1 작업방입니다. |
| 팀과 같이 이야기 | **채널** | 사람들과 AI가 함께 보는 대화방입니다. |
| 문서·코드·자료 확인 | **파일 탭** | 프로젝트 폴더의 파일을 보고 편집합니다. |
| 결과물 만들기 | **대화에서 요청** | 보고서, PDF, HTML, 엑셀, 슬라이드, 코드 등을 만들 수 있습니다. |
| 만든 웹페이지 공유 | **게시/Publish** | 정적 HTML 결과물을 안전한 링크로 공유합니다. |
| 반복 작업 예약 | **스케줄/태스크** | 매일/매주 요약, 알림, 점검을 예약합니다. |
| AI 능력 확장 | **스킬** | PPT, PDF, 검색, Google Workspace 같은 전용 작업법입니다. |
| 반복 가능한 자동화 | **스킬/스케줄** | 복잡하고 미묘한 순서도 다음에 같은 품질로 다시 실행합니다. |
| 결정·인계 남기기 | **파일/결정문서** | 오늘의 판단을 미래의 조직 기억으로 남깁니다. |

## Tower가 일반 챗봇과 다른 점

### 1. 대화가 파일과 연결됩니다

AI가 만든 문서나 분석 결과는 프로젝트 폴더에 남길 수 있습니다. 그래서 “지난번 답변 어디 있지?”가 아니라, **파일 탭에서 산출물을 다시 열고 수정**할 수 있습니다.

### 2. 프로젝트마다 규칙이 다릅니다

각 프로젝트에는 `AGENTS.md`라는 운영 안내서가 있을 수 있습니다. AI는 그 프로젝트의 말투, 파일 위치, 금지 사항, 작업 방식 같은 맥락을 참고합니다.

### 3. 공유 서버입니다

Tower는 혼자 쓰는 로컬 앱이 아닙니다. 여러 사용자가 같은 서버와 워크스페이스를 씁니다. 그래서 파일 위치, 권한, 배포, 커밋 같은 작업은 조심스럽게 처리합니다.

### 4. AI가 실제 산출물을 만듭니다

텍스트 답변만 하는 것이 아니라 다음 일을 할 수 있습니다.

- 파일 읽기·수정·생성
- Excel/PDF/이미지/CAD 자료 분석
- HTML/PDF/DOCX/슬라이드 산출물 제작
- 정적 사이트 게시
- Git 커밋/PR 준비
- 반복 스케줄 등록
- 과거 대화 검색과 인계

## 가장 흔한 사용 흐름

### 문서나 보고서를 만들 때

1. 프로젝트를 선택합니다.
2. 새 세션을 엽니다.
3. “이 자료를 바탕으로 보고서 초안 만들어줘”처럼 요청합니다.
4. AI가 만든 파일 경로를 클릭하거나 파일 탭에서 엽니다.
5. 마음에 안 드는 부분을 다시 대화로 수정 요청합니다.

### 첨부 파일을 분석할 때

1. 파일을 채팅 입력창에 드래그합니다.
2. “핵심 요약, 리스크, 다음 액션으로 정리해줘”라고 요청합니다.
3. PDF나 엑셀처럼 레이아웃이 중요한 자료는 AI가 시각적으로 확인할 수 있습니다.
4. 필요하면 Markdown, Excel, PDF 같은 결과물로 저장합니다.

### 웹페이지나 대시보드를 공유할 때

1. AI에게 HTML 페이지나 대시보드를 만들게 합니다.
2. 프로젝트 안에 `index.html`이 있는 폴더를 만듭니다.
3. 게시하면 Tower가 외부 공유 URL을 만들어 줍니다.
4. 기본은 추측하기 어려운 **비공개에 가까운 공유 링크(unlisted)**입니다.

### 정기적으로 AI가 일하게 할 때

1. “매일 오전 9시에 어제 대화 요약해줘”처럼 말합니다.
2. AI가 스케줄 내용을 확인합니다.
3. 확인 후 Tower 스케줄에 등록합니다.

### 자주 쓰면 좋은 고급 활용

| 하고 싶은 일 | 이렇게 말해보세요 | 왜 좋은가요? |
|---|---|---|
| 결정문서 남기기 | “이 판단을 결정문서로 기록해줘” | 결정은 곧 미래의 조직 기억입니다. 나중에 사람이 바뀌어도 왜 그렇게 했는지 추적할 수 있습니다. |
| 자동화/스킬 만들기 | “이 작업 순서를 스킬로 만들 수 있을지 봐줘” | 복잡하고 미묘한 뉘앙스, 확인 순서, 산출물 형식을 다음에도 같은 방식으로 재현할 수 있습니다. |
| 서브에이전트 호출 | “보안 리뷰와 UX 리뷰를 나눠서 검토해줘” | 큰 일을 여러 관점으로 나눠 동시에 검토하고, 마지막에 결론을 합칠 수 있습니다. |
| HTML 만들고 게시 | “인터랙티브 HTML 보고서를 만들고 게시 가능한 링크로 공유해줘” | 문서보다 보기 쉽고, 링크 하나로 고객·팀원에게 보여줄 수 있습니다. |

## 초보자가 기억해야 할 7가지

1. **프로젝트를 먼저 확인하세요.** 파일과 대화는 프로젝트 기준으로 정리됩니다.
2. **파일은 파일 탭에서 봅니다.** AI가 만든 산출물은 경로를 클릭하면 바로 열 수 있습니다.
3. **긴 일은 한 세션에 모으세요.** 맥락이 이어져 결과가 좋아집니다.
4. **중요한 결정은 문서로 남기세요.** 결정문서는 미래의 팀원이 읽는 조직 기억입니다.
5. **공유/게시/삭제/배포는 조심하세요.** 다른 사람에게 영향을 줄 수 있습니다.
6. **스킬은 전용 작업 모드입니다.** PPT, PDF, 검색, 회의 준비처럼 특정 일을 더 안정적으로 반복합니다.
7. **AI가 모르면 물어보게 하세요.** 중요한 방향이 갈리는 경우에는 먼저 맞추고 가는 것이 좋습니다.

## AI에게 이렇게 말하면 좋습니다

나쁜 요청:

> 이거 해줘.

좋은 요청:

> 이 PDF를 초보자도 이해하게 1페이지 요약으로 정리해줘. 핵심 결론, 근거 3개, 리스크, 다음 액션을 나눠줘. 결과는 Markdown 파일로 저장해줘.

더 좋은 요청:

> 대상은 임원이고, 너무 기술적인 말은 줄여줘. 불확실한 내용은 추정이라고 표시해줘. 파일은 프로젝트의 `work/` 아래에 저장해줘.

## 헷갈릴 때의 기준

- **대화만 필요**하면 세션
- **팀과 같이 봐야** 하면 채널
- **다시 열 산출물**이면 파일로 저장
- **외부에 보여줄 결과**면 PDF/DOCX/HTML/게시 링크
- **반복될 일**이면 스케줄
- **회사나 프로젝트 규칙**이면 `AGENTS.md` 또는 결정문서

처음에는 완벽히 알 필요 없습니다. 원하는 결과를 자연어로 말하면 AI가 필요한 절차를 안내합니다.
