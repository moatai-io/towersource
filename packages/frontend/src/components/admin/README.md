# Admin user settings

`AdminPanel.tsx` owns the scrollable admin shell; `UserManagement.tsx` owns user actions and the responsive user surface. At widths below 1024px, the user table is **not mounted**: a single-column summary list opens one user's details and actions, avoiding duplicate focusable controls/IDs. At desktop widths the existing table remains. The signup invite section is collapsed by default on compact screens and can be expanded without changing its API behavior. Search and state filters apply to either layout. The default list shows non-disabled accounts (including pending approval); disabled accounts are collapsed in a separate section with a count. An explicit disabled filter reveals them immediately, and searching includes matching disabled accounts rather than silently hiding them. Display name, login ID, account email/verification, and account status remain separate labels.

The compact surface calls the same handlers and permission guards as desktop for approvals, role, email, reset, edit, disable and reactivate. Do not add a second CSS-hidden interactive table. Edit uses a scrollable, labelled dialog; back/close restore focus. Login history is historical, not online status.

Tests: `AdminPanel.user-list.source.test.ts` (collapsed/search policy), `AdminPanel.account-email.source.test.ts`, `AdminPanel.password-recovery.source.test.ts`, `AdminPanel.responsive-layout.source.test.ts`, `e2e/admin-account-email.spec.ts` and `e2e/admin-users-mobile.spec.ts`. The browser specs use an isolated Vite port and intercept `/api/**` with synthetic users; they must never use real admin credentials or send mail.
